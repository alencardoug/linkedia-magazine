# Visual: reading modes (the weekly lab is retired)

## Reading modes (V2-06, engine decision D-081)
The reading pages (every page on `src/layouts/Base.astro`, `/visual` included) have three modes: **light**, **dark** and **black**.

- **Default.** Without a stored pick the pages follow the system's `prefers-color-scheme` and its changes: light or dark. Black is never chosen automatically.
- **Button.** A discreet button at the top right of the header cycles light → dark → black → light and stores the pick. Its accessible name says the mode on screen ("Modo de leitura: Escuro"), its description says the next one ("Muda para o modo preto."), and a polite live region announces each change ("Modo preto ativado."). Narrow screens (≤ 30rem) show the icon only; the name stays for screen readers. Without JS the button stays hidden (its room is kept: `visibility: hidden`) and the system mode applies.
- **Storage.** One versioned key, `localStorage["linkedia:modo:v1"]`, value `light`, `dark` or `black`; any other value is no pick. Every read and write is wrapped in `try/catch`: with storage blocked the pick lasts for the page view. The retired theme key `linkedia:tema` is removed on the first visit. A pick in another tab reaches open pages (`storage` event); a page restored from the back/forward cache re-reads it.
- **No flash.** `public/modo.js` is a classic same-origin script loaded **blocking** as the first element after `<meta charset>`: it sets `data-mode` on `<html>` before the body is parsed. No inline script, so the CSP `script-src` is `'self'` only (the hash of the retired theme script is gone). The button's module (`src/lib/mode.ts`) is bundled by Astro.
- **Tokens.** `src/styles/site.css` (was `themes/minimal-dark/theme.css`) defines one set of custom properties (`--bg`, `--surface`, `--border`, `--fg`, `--muted`, `--accent`, `--accent-strong`, `--warning`, `--focus`, `--on-focus`) per mode: light under `:root`, dark under `@media (prefers-color-scheme: dark) { :root:not([data-mode]) }` and each explicit pick under `:root[data-mode="…"]`. The WCAG contrast of each pair is in the file header (all text ≥ 4.5:1 on `--bg` and `--surface`).
- **Out of scope.** Cover pages (`/`, `/visual/<slug>`) keep their own palette and never load `modo.js`; art-directed specials (`SpecialLayout.astro`) keep their own light/dark choice; guide sites on other origins keep theirs.
- **Tests.** `tests/mode.test.mjs` (rules, bootstrap in a fake DOM), `tests/build.test.mjs` (bootstrap first in `<head>`, blocking; button markup; one stylesheet with the three modes; nothing of the retired system), `tests/firebase.test.mjs` (CSP without hash, `/modo.js` cache), `e2e/modes.spec.mjs` (first frame and a screenshot pixel in each system/pick pair; keyboard cycle, name, description and live region; system changes; invalid values; blocked storage; other tabs; no JS; covers and specials untouched; axe at 1100 px and 320 px without scroll or layout shift on every kind of reading page in the three modes, screenshots in `test-results/screenshots/<mode>/`, CI artifact `mode-screenshots`).

## The weekly lab (1C, D-025/D-063/D-064/D-066/D-070) — retired
From 1C-01 to V2-06 the site had a three-slot theme switcher on `/visual` (the `minimal-dark` baseline, the fixed "Broadsheet" and a weekly "Atual" experiment), lab themes under `themes/lab-YYYY-wWW/`, a manifest (`themes/manifest.json`, `contracts/theme_manifest.schema.json`), a Vite plugin, a runtime with lazy enhancements and `npm run theme:rollover`. The owner retired it (D-081, 2026-11-20): the weekly creative work lives on in the covers (`docs/COVERS.md`). Every past theme is recoverable from Git: the last commit with the system is the parent of the V2-06 commit (themes `lab-2026-w42` "Broadsheet" and `lab-2026-w43` "Singularidade"). Editions keep their `visual_theme_id` as a legacy field (optional in both contract versions; the v1 exporter writes `null` once the manifest is gone).
