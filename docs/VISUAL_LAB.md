# Visual: reading modes (the weekly lab is retired)

## Reading modes (V2-06, engine decision D-081)
The reading pages (every page on `src/layouts/Base.astro`, `/visual` included) have three modes: **light**, **dark** and **black**.

- **Default.** Without a stored pick the pages follow the system's `prefers-color-scheme` and its changes: light or dark. Black is never chosen automatically.
- **Button.** A discreet button at the top right of the header cycles light → dark → black → light and stores the pick. Its accessible name says the mode on screen ("Modo de leitura: Escuro"), its description says the next one ("Muda para o modo preto."), and a polite live region announces each change ("Modo preto ativado."). Narrow screens (≤ 30rem) show the icon only; the name stays for screen readers. Without JS the button stays hidden (its room is kept: `visibility: hidden`) and the system mode applies.
- **Storage.** One versioned key, `localStorage["linkedia:modo:v1"]`, value `light`, `dark` or `black`; any other value is no pick. Every read and write is wrapped in `try/catch`: with storage blocked the pick lasts for the page view. The retired theme key `linkedia:tema` is removed on the first visit. A pick in another tab reaches open pages (`storage` event); a page restored from the back/forward cache re-reads it.
- **No flash.** `public/modo.js` is a classic same-origin script loaded **blocking** as the first element after `<meta charset>`: it sets `data-mode` on `<html>` before the body is parsed. No inline script, so the CSP `script-src` is `'self'` only (the hash of the retired theme script is gone). The button's module (`src/lib/mode.ts`) is bundled by Astro.
- **Looks (V2-06b, D-085).** Light = **Broadsheet** (newsprint: serif text, red accent, centred masthead, double rules, drop caps), dark = **Singularidade** (navy under the cover's dot grid, heavy sans masthead with the pink-to-amber "ia", kicker labels, amber links), black = **minimal-dark** (the 1B baseline). All live in `src/styles/site.css`: black is the base stylesheet; light and dark are `@mode light { … }` / `@mode dark { … }` blocks, written once and expanded at build time by `scripts/css-modes.mjs` (PostCSS, `astro.config.mjs`) into the explicit pick (`:root[data-mode="…"]`) and the system default without a pick (`@media (prefers-color-scheme: …) { :root:not([data-mode]) … }`), so the system look needs no JS and both paths match. Both looks draw a reading-progress rule (CSS scroll-driven) only without reduced motion. Contrast figures are in each block's header.
- **Out of scope.** Cover pages (`/`, `/visual/<slug>`) keep their own palette and never load `modo.js`; art-directed specials (`SpecialLayout.astro`) keep their own light/dark choice; guide sites on other origins keep theirs.
- **Tests.** `tests/mode.test.mjs` (rules, bootstrap in a fake DOM), `tests/css-modes.test.mjs` (the `@mode` expansion), `tests/build.test.mjs` (bootstrap first in `<head>`, blocking; button markup; one stylesheet with the three modes; nothing of the retired system), `tests/firebase.test.mjs` (CSP without hash, `/modo.js` cache), `e2e/modes.spec.mjs` (first frame and a screenshot pixel in each system/pick pair; keyboard cycle, name, description and live region; system changes; invalid values; blocked storage; back/forward restore; other tabs; no JS; covers and specials untouched; reduced motion and forced colours; axe at 1100 px and 320 px without scroll or layout shift on the four distinct layouts — `/revista`, an article, `/edicoes`, `/visual` — in each mode, screenshots at both widths in `test-results/screenshots/<mode>/`, CI artifact `mode-screenshots`; every other route gets axe and 320 px in the system default through `e2e/smoke.spec.mjs`).

## The weekly lab (1C, D-025/D-063/D-064/D-066/D-070) — retired
From 1C-01 to V2-06 the site had a three-slot theme switcher on `/visual` (the `minimal-dark` baseline, the fixed "Broadsheet" and a weekly "Atual" experiment), lab themes under `themes/lab-YYYY-wWW/`, a manifest (`themes/manifest.json`, `contracts/theme_manifest.schema.json`), a Vite plugin, a runtime with lazy enhancements and `npm run theme:rollover`. The owner retired it (D-081, 2026-11-20): the weekly creative work lives on in the covers (`docs/COVERS.md`). Broadsheet and Singularidade live on as the light and dark looks (V2-06b); the lab machinery stays in Git (the parent of the V2-06 commit). Editions keep their `visual_theme_id` as a legacy field (optional in both contract versions; the v1 exporter writes `null` once the manifest is gone).
