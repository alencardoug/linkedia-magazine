# Static Magazine Experience

## Minimal navigation, maximum exploration
On opening the homepage, lead with one extraordinary presentation of **today's published issue**, not a cluttered analytics dashboard. Readers can reach older issues through one unobtrusive archive link, or navigate by category and tags. The 3 categories do not require permanent tabs; any accessible design metaphor is allowed. Feature important stories visually rather than enforcing equal category blocks.

## Routes
- `/`: most recent available edition, not necessarily today's calendar date.
- `/edicoes`: simple archive by date, with filters for channels/tags when useful.
- `/edicoes/YYYY-MM-DD`: fixed daily edition.
- `/materias/{slug}`: article permalink.
- `/categorias/{canal}`: published articles of one channel, pt-BR slugs `engenharia-de-ia`, `lideranca-de-ia`, `conhecimento-de-ia` (1B-01).
- `/tags/{tag}` may be added when useful; avoid complexity in phase 1B.

As built (1B-01): content comes from `LINKEDIA_CONTENT_DIR` (default `content`; tests build `content/examples` and a hostile fixture) through `src/lib/content.ts`; an article page exists for every article listed in some edition. Blocks render as escaped text (`src/components/Block.astro`): code and diagram specs in `<pre><code>`, a diagram as a `<figure>` with its long description and the spec in `<details>` (D-027), an image only from a host in `IMAGE_HOSTS` (empty, D-026) else its text fallback. Each article ends with its prompts (`<details>` with selectable text; a copy button appears only with JS and reports in `aria-live`), the AI note and the numbered source list that block citations link to.

## Page layout
Dynamic visual hero/artwork + compact article discovery, with graceful fallback. Article reading layout prioritizes line length, excellent typography, source list, jump-back navigation and small prompt-copy controls. Avoid weighty client-side search index at the outset. A site with no edition for a day simply shows the last published edition.

## Rendering model
Astro builds static pages from `content/editions` and `content/articles` JSON. Validate each article against the public schema at build time. Client JS only where needed: vanilla TS for prompt-copy controls (1B) and the theme switcher (1C); React only inside a lab theme that needs it, lazy-loaded. Images are remotely hosted from approved sources with fallbacks; authored SVG/CSS/Canvas art is acceptable without embedding large image binaries. No bundled image files by default.

## Accessible prompts
`Saber mais` and other mini actions copy an editorially prepared Portuguese prompt to the clipboard; announce copy success in `aria-live` text, and provide selectable text fallback if clipboard access is denied. No direct ChatGPT API or account dependence.

## Transparency and privacy
- AI disclosure (engine decision D-028): a "Sobre" page explains how editions are made (sources collected, topics chosen by a human editor, text generated by AI, automatic checks) and every article shows a short note plus its sources. `editorial_metadata.ai_generated` is always true.
- No analytics, no cookies, no third-party requests (fonts self-hosted or system stack; no remote images in the MVP). The only stored data is the reader's theme choice in `localStorage`.
